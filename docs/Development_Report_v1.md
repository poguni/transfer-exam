# 편입 캘린더(TExam Calendar) 개발 보고서 (v1)

- 작성일: 2026-11-17
- 버전: v1

## 1. 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | 편입 캘린더(TExam Calendar) |
| 한 줄 소개 | 2027학년도 대학 편입 시험 일정을 2026년 11월 ~ 2027년 2월 4개월 달력 한 곳에서 관리하는 가족용 웹 앱 |
| 대상 사용자 | 편입 준비생(자녀) 1명과 부모. 같은 데이터를 각자의 기기에서 봄 |
| 사용 방식 | 입력은 주로 데스크톱, 아이폰은 확인용(시험 당일 정보, D-day) |
| 배포 주소 | https://poguni.github.io/transfer-exam/ (GitHub Pages) |

## 2. 목표 및 배경

편입 시험은 12월부터 이듬해 1월까지 치르고, 수험생 한 명이 10곳 넘게 지원하는 일이 흔합니다. 대학마다 원서 접수, 필기시험, 1단계 발표, 서류 제출, 면접, 최종 발표, 등록, 충원 일정이 따로 있고, 같은 날 오전·오후로 두 대학 시험이 겹치기도 합니다. 일정과 수험 번호, 시험 장소, 교통 정보가 대학 홈페이지와 원서 접수 사이트에 흩어져 있어 한눈에 보기 어렵습니다.

이 앱이 지향하는 핵심 가치는 다음과 같습니다.

- 11월 ~ 2월 모든 일정을 달력 한 곳에서 보기
- 시험 당일 화면 하나로 입실 시각·권장 출발 시각·수험 번호·장소·준비물 확인
- 다음 시험까지 남은 날(D-day)과 일정 겹침을 자동으로 알려 주기
- 아이폰 캘린더 알림(.ics), A4 인쇄(벽에 붙이기)
- 자녀와 부모가 같은 데이터를 함께 보기

## 4. 기술 스택 및 아키텍처

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React 19 + TypeScript 7 + Vite 8 | 화면이 여러 개이고 상태가 얽혀 컴포넌트 구조가 편함. 정적 파일로 배포 가능 |
| 화면 이동 | React Router 8 `HashRouter` | GitHub Pages에서 새로고침해도 404가 나지 않음 |
| 스타일 | CSS 변수(디자인 토큰) + 컴포넌트 CSS, Tailwind 4 `@theme` 연결 | 테마는 `data-theme` 속성 하나로 토큰만 교체 |
| 서버 상태 | TanStack Query 5 | 캐시, 다시 불러오기, 창 포커스 시 갱신 |
| 날짜 | date-fns 4 + `@date-fns/tz` | 서울 날짜 계산을 함수 단위로 테스트 |
| 백엔드 | Supabase(기존 Link Plan 프로젝트 공유) | 로그인 계정 공유, DB·RLS·Realtime 한 번에 |
| 테스트 | Vitest 5(계산 함수), Playwright(화면·PDF) | 계산 규칙은 단위 테스트, 화면은 가짜 백엔드로 흐름 확인 |
| 배포 | GitHub Pages + GitHub Actions | 무료·HTTPS, 사용자가 직접 관리하는 저장소 |

### 데이터 모델 (Supabase, 접두사 tcal_)

| 테이블 | 내용 |
|---|---|
| tcal_families | 가족, 초대 코드, 가족 공유 설정(jsonb) |
| tcal_family_members | 구성원(자녀/부모), 표시 이름 |
| tcal_universities | 지원 대학(A~H 항목), 테스트 표시 `is_sample` |
| tcal_events | 일정 10종(서울 날짜·시각을 date·time으로 따로 저장) |
| tcal_documents | 준비 서류와 진행 상태 |
| tcal_checklist_items | 시험 당일 준비물 |

- 모든 테이블에 RLS를 걸고, 같은 가족만 읽고 쓰게 했습니다(`tcal_is_member` 함수).
- 가족 만들기와 초대 코드 참여는 `security definer` 함수(`tcal_create_family`, `tcal_join_family`)로만 합니다.
- 수정 시각·수정한 사람 자동 기록, 하위 테이블의 가족 일치 검사 트리거를 두었습니다.

## 6. 주요 의사결정과 이유

| 결정 | 이유 |
|---|---|
| 데스크톱을 먼저 만들고 반응형으로 아이폰까지 | 입력은 주로 데스크톱, 아이폰은 확인용이라는 사용 방식(사용자 결정) |
| 데스크톱은 화면 전체 폭 사용, max-width 틀 금지 | 가운데 몰리고 좌우가 비는 화면을 피하기 위해(사용자 요청). 달력 칸·표·폼이 폭에 맞춰 늘어남 |
| 달력 기본 보기는 1개월 크게 + 오른쪽 패널 | 사용자 선택. 넓은 칸에 "●건국 필기 09:30"처럼 종류·시각까지 표시 |
| 일정 입력은 오른쪽 패널, 대학 등록은 전체 폭 페이지 | 달력을 보면서 날짜를 고르고, 항목이 많은 대학 폼은 넓게(사용자 선택) |
| 코드 전에 데스크톱 시안으로 확인 | 데스크톱 시안이 없던 상태에서 방향을 먼저 맞추기 위해 |
| 해시 라우팅 + 상대 경로 base('./') | 저장소 이름과 상관없이 GitHub Pages에서 동작, 새로고침 404 없음 |
| 순수 계산 함수 분리(lib)와 단위 테스트 | D-day·겹침·.ics는 경계값 실수가 치명적이라 PRD 완료 기준을 테스트로 고정 |
| 날짜·시각을 문자열과 정수 날짜로 계산 | 기기 시간대와 상관없이 서울 기준 같은 결과 |
| 가족 만들기를 DB 함수 하나로 | 가족과 첫 구성원이 함께 생겨 "구성원 없는 가족"이 남지 않음 |
| 실시간 반영은 Broadcast 신호 | DB publication을 바꾸지 않아 Link Plan 보호 규칙을 지킴. 신호에는 데이터가 없음 |
| 오프라인은 서비스 워커(앱 화면) + localStorage(데이터) | 의존성 없이 단순하게. 로그아웃하면 보관 데이터 삭제 |
| 테스트 데이터는 is_sample 표시로 구분 | 일괄 삭제가 실제 데이터를 절대 건드리지 않게 |
| 화면 확인은 가짜 Supabase로 | 운영 DB(Link Plan)에 테스트 데이터를 남기지 않고, 계정 비밀번호 없이 전체 흐름 확인 |
| Git은 사용자가 직접 | 사용자 요청. Claude는 커밋 시점과 메시지만 제안 |

## 7. 문제 해결 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| 앱이 tcal_ 테이블을 전혀 읽지 못할 뻔함 | 이 Supabase 프로젝트는 새 테이블에 anon·authenticated 권한을 자동으로 주지 않음 | RLS 검증 중 발견. authenticated에만 필요한 권한을 주는 마이그레이션 추가, anon의 TRUNCATE(RLS 우회 가능)도 회수 |
| 운영 DB에서 RLS를 검증해야 함 | 테스트 데이터를 남기면 안 됨 | do 블록 안에서 역할을 바꿔 확인하고 마지막에 예외를 일으켜 전부 되돌림 |
| 상세 패널 카드 아래쪽이 잘림 | flex 열 안의 카드가 줄어듦 | 패널·페이지 안 요소에 flex-shrink 0 |
| 4개월 보기로 바꾸면 패널이 달력을 가림 | 날짜 지정 진입 시 열린 패널이 유지됨 | 보기를 바꾸면 패널을 닫고 Esc로도 닫게 함 |
| 시각을 넣기 전부터 "간격 주의" 경고 | 시각 없는 일정은 규칙상 주의 | 시각 입력 전에는 안내만 표시 |
| 인쇄 칸에서 수험 번호·시각이 잘림 | 좁은 칸에서 한 줄 고정 | 세로형은 조각 단위로 다음 줄로 넘김 |
| .ics 알림 순서가 규격과 다름 | VALARM이 일정 속성보다 앞에 있었음 | RFC 5545대로 속성 뒤로 이동, 테스트 추가 |
| 배포 후 빈 화면 | 빌드 시 Supabase 변수가 비어 앱이 시작하자마자 멈춤(배포는 초록색) | Repository variables 안내, 변수가 비면 워크플로가 실패하고 앱은 안내 화면을 보여 주게 함 |
| 실시간 신호 경고 | 연결 전 send가 곧 지원이 끊길 REST 우회로 감 | 연결된 동안에만 신호 전송 |
| 테스트 실행 환경 제약 | 로컬 서버 실행 거부, Playwright에서 require·import 불가 | Playwright 경로 가로채기로 dist 제공, 가짜 백엔드를 실행 함수 파일 하나로 구성 |

## 8. 보안/성능 고려사항

### 보안

- 모든 tcal_ 테이블에 RLS, 같은 가족만 조회·수정. 가족이 아닌 계정과 로그인하지 않은 접근은 거부됨을 검증
- 로그인하지 않은 사용자(anon)에게는 테이블·함수 권한을 주지 않음
- 함수는 `search_path = ''`로 고정
- 클라이언트에는 공개(publishable) 키만, service_role 키는 어디에도 두지 않음
- Link Plan의 기존 테이블·함수·트리거·Auth 설정은 읽기만 함(CLAUDE.md 규칙)
- 수험 번호를 인쇄에서 숨기는 옵션, 로그아웃 시 기기 보관 데이터 삭제

### 성능

- 가족 데이터를 한 번에 불러옴(대학 20곳·일정 100개 이하 가정)
- 고른 테마의 글꼴만 불러옴. 프리텐다드는 플래너일 때만 따로 받음
- 빌드 파일은 서비스 워커가 보관해 다시 열 때 빠름

## 10. 배포

- 방식: GitHub Actions(`.github/workflows/deploy.yml`)가 main에 올라올 때 변수 확인 → npm ci → 테스트 → 빌드 → GitHub Pages 배포
- 주소: https://poguni.github.io/transfer-exam/
- 필요한 설정: 저장소 Settings › Pages Source를 GitHub Actions로, Settings › Secrets and variables › Actions › Variables의 **Repository variables**에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
- 아이폰: Safari에서 열고 공유 › 홈 화면에 추가
- 이메일·비밀번호 로그인이라 Supabase Auth의 Site URL·Redirect URL은 바꾸지 않음

## 11. 알려진 한계

- 회원가입 화면이 없음: 부모 계정은 Supabase 대시보드(Authentication › Users)나 Link Plan에서 만든 뒤 초대 코드로 참여
- "변경된 일정만" 내보내기의 기준 시각은 기기마다 따로 기록됨
- 앱에서 삭제한 일정은 아이폰 캘린더에서 자동으로 지워지지 않음(구독 주소가 필요)
- 기기 기본 시각 선택기는 OS 언어에 따라 "오전/오후"로 보일 수 있음(저장 후 확인 문구는 24시간 표기)
- 오프라인에서는 보기만 가능하고 저장은 연결된 뒤에만 가능. 끊긴 것을 알리는 안내는 Supabase 재시도 때문에 약 15초 뒤에 나타남
- 공휴일(2/9 대체공휴일 등)은 코드 상수라 정부 공고가 바뀌면 직접 고쳐야 함
- Safari는 인쇄 용지 방향 설정을 무시할 수 있어 데스크톱 크롬 인쇄를 기준으로 함
- 빌드 결과 JS가 하나의 큰 파일(약 620KB)로 나옴
